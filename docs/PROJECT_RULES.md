# PROJECT_RULES.md

## 1. Purpose

These rules define how the Stratifit Digital Agency platform and CMS are built and maintained.
All contributors — human and AI — must follow these standards without exception.

### Tech Stack

* **Framework:** Next.js (App Router)
* **Language:** TypeScript (Strict Mode)
* **Styling:** Tailwind CSS
* **Animation:** GSAP (`@gsap/react`)
* **Backend & Auth:** Supabase (Postgres, Auth, Storage, Edge Functions)
* **Specs & Tasks:** OpenSpec (`openspec/`)
* **Code Review:** Open Code Review (`.opencode/`)
* **Primary IDE:** Zed Editor

---

## 2. Repository Structure

```text
src/          → Application source code (app router, components, hooks, lib)
public/       → Static assets (images, fonts, vector icons)
docs/         → Project documentation (rules, architecture, CMS, design system)
openspec/     → Feature specs, change logs, task tracks, config.yaml
supabase/     → Schema migrations, SQL scripts, RLS policies, seeds
.opencode/    → OpenCode commands, skills, and agent execution logic

```

* **Strict Rule:** No application or feature code may exist outside `src/`.

---

## 3. Naming Conventions

### Files & Folders

* **Components & Utilities:** `kebab-case.tsx` / `kebab-case.ts`
* **Hooks:** `use-something.ts`
* **App Router Special Files:** `page.tsx`, `layout.tsx`, `loading.tsx`, `error.tsx`, `route.ts`

### Code Symbols

* **React Components:** `PascalCase`
* **Type Definitions:** `PascalCase` (`UserProps`, `NavigationConfig`, `AuthResponse`)
* **Functions & Variables:** `camelCase`
* **Constants & Env Vars:** `UPPER_SNAKE_CASE`

### Tailwind Usage

* Utility-first approach.
* **No arbitrary/magic values** (e.g., avoid `w-[342px]` or `bg-[#1a1a1a]`).
* All spacing, colors, radii, and shadows must reference tokens defined in `DESIGN_SYSTEM.md` / `tailwind.config.ts`.

---

## 4. TypeScript Rules

* `strict` mode is enabled in `tsconfig.json` and strictly enforced.
* `any` is forbidden unless explicitly justified with an inline `//-eslint-disable` and rationale comment.
* Use `type` aliases for all data models, props, and state definitions.
* All component props must be fully typed.
* Global and shared domain types reside in `src/lib/types/`.

---

## 5. Tailwind & Styling Rules

* Only use brand and system color tokens declared in `DESIGN_SYSTEM.md`.
* Structural/layout components (`containers`, `grids`, `flex` wrappers) handle layout.
* Atomic UI components handle visual styling (borders, backgrounds, typography).
* Always leverage Tailwind's native responsive (`sm:`, `md:`, `lg:`) and state variants (`hover:`, `focus-visible:`, `active:`).

---

## 6. Motion & GSAP Rules

* GSAP is the standard library for non-trivial animation and micro-interactions.
* **Lifecycle Management:** All GSAP animations inside React components **must** use the `@gsap/react` `useGSAP()` hook or clean up effects via `gsap.context()` to prevent memory leaks in React Strict Mode.
* **Accessibility:** Respect `prefers-reduced-motion` settings with instant fallbacks or reduced movement parameters.
* **Performance:** Avoid animating layout properties (`width`, `height`, `top`). Stick to `transform` (`x`, `y`, `scale`) and `opacity`.
* Shared animation presets must be documented in `DESIGN_SYSTEM.md`.

---

## 7. Git, Specs & Code Review Rules

* `main` is protected — direct pushes are disabled.
* All development occurs on isolated feature or fix branches (`feat/`, `fix/`, `chore/`).
* **OpenSpec Sync:** Any PR adding or modifying features must include the relevant spec updates in `openspec/`.
* Commit messages must adhere to **Conventional Commits**:
* `feat:`, `fix:`, `docs:`, `refactor:`, `style:`, `perf:`, `chore:`


* All Pull Requests must pass `.opencode/` automated reviews and check passes prior to merging.

---

## 8. Environment & Secrets

* Never commit secrets, service-role keys, or private API credentials to version control.
* Store local environment variables in `.env.local` (ignored by Git).
* Separate configurations strictly across:
* Local Development
* Staging / Preview
* Production



---

## 9. AI & Multi-Agent Collaboration

* AI tools (OpenCode, Copilot, Zed Assistant) act as drafting assistants; human reviewers hold final authority.
* Code generated by AI must adhere to:
* `PROJECT_RULES.md`
* `COMPONENT_STANDARDS.md`
* `DESIGN_SYSTEM.md`
* `CMS.md`


* AI agents are prohibited from introducing new dependencies or structural patterns without explicit updates to `openspec/` and `docs/`.

---

## 10. Document Governance

Updates to this document require:

1. A proposed pull request with context.
2. Cross-verification against `ARCHITECTURE.md`, `DESIGN_SYSTEM.md`, `CMS.md`, and `COMPONENT_STANDARDS.md` to ensure zero conflicting rules.
